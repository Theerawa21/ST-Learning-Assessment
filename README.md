# ST-Learning Assessment

เว็บวิเคราะห์ตัวชี้วัด/ผลการเรียนรู้และการวัดประเมินผล สำหรับโรงเรียนเซนต์เทเรซา

รองรับหน้าเว็บ GitHub Pages + Google Apps Script + Google Sheets + Google Drive หน้าจอภาษาไทยรองรับคอมพิวเตอร์และมือถือ โทนแดงเข้ม–ครีม ฟอนต์ Sarabun

## เปิดเว็บผ่าน GitHub

ดู [คู่มือตั้งค่า GitHub Pages](docs/GITHUB-PAGES.md) โค้ดหน้าเว็บและ workflow พร้อมแล้ว ต้องเปิด Pages ตั้งค่า Google OAuth origin และเผยแพร่ Apps Script รุ่นที่มี StaticBridge ก่อนใช้งานจริง

```powershell
node tools/build-pages.cjs
```

## เริ่มใช้งาน

เริ่มจาก [รายการส่งมอบสำหรับผู้ดูแลโรงเรียน](docs/ADMIN-HANDOFF.md) แล้วทำตาม [คู่มือติดตั้ง](docs/INSTALL.md) และ [รายการตรวจรับ](docs/TEST-RESULTS.md) แพ็กเกจ editor แบบ 3 ไฟล์อยู่ใน `release/editor-bundle/` และ ZIP แยก `ST-Learning-Assessment-Apps-Script-Editor.zip` อยู่ข้างโฟลเดอร์โครงการ

1. สร้างโครงการ Apps Script ในบัญชี Google ของโรงเรียนและนำไฟล์ใน `src/` เข้าโครงการ
2. ตั้ง Script Properties แล้วรัน `setupSystem`
3. เพิ่มผู้ใช้ กลุ่มสาระ หลักสูตร รายวิชา และนำเข้าตัวชี้วัดที่โรงเรียนตรวจสอบแล้ว
4. เผยแพร่เป็น Web app ตามคู่มือ แล้วทดสอบสิทธิ์ด้วยบัญชีจริงก่อนใช้รับงาน

ระบบ Apps Script เดิมเผยแพร่แล้ว ส่วนการย้ายหน้าเว็บไป GitHub Pages ยังรอตั้งค่าการเผยแพร่และทดสอบการเข้าสู่ระบบบนโดเมนใหม่

## ส่วนที่พัฒนา

- สิทธิ์ 5 บทบาทและหลายบทบาทต่อบัญชี ตรวจทุก API ที่ server ไม่เชื่อ role/email จาก browser
- ข้อมูลผู้ใช้ กลุ่มสาระ หลักสูตรหลายรุ่น รายวิชาและการมอบหมายครู
- นำเข้า CSV/Google Sheets พร้อมตรวจแถวผิดและข้อมูลซ้ำ ไม่มีตัวชี้วัดสมมติในระบบจริง
- ตาราง 5 คอลัมน์ รวมหลายตัวชี้วัด เครื่องมือหลายชนิด และเลือกช่วงได้ 1–4 ช่วง
- ร่าง การตรวจความครบถ้วน รุ่นเอกสาร และป้องกันการเขียนทับจากหน้าจอเก่า
- ตรวจ 3 ระดับ Checklist 9 ข้อ ความเห็นรายข้อ/รายแถว ส่งกลับและเริ่มตรวจใหม่
- ห้ามรับรองงานตนเอง ห้ามข้ามขั้น ล็อกฉบับอนุมัติ และสร้างฉบับปรับปรุง
- รายงาน PDF/DOCX/XLSX/Google Docs แบบจำกัดสิทธิ์ไฟล์ แจ้งเตือนภายในระบบ
- อีเมลแบบ opt-in, ประวัติเข้าสู่ระบบ/ทำรายการ, สำรองรายวัน และกู้คืนเป็นสำเนา
- LockService, optimistic revision, expected workflow status และ request ID ป้องกันคำสั่งซ้ำ

## ดูตัวอย่างบนเครื่อง

ต้องมี Node.js 20 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่มเติม

```powershell
node tools/preview.cjs
```

เปิด `http://127.0.0.1:4187` โหมดนี้มีแถบสีเหลืองระบุว่าเป็นข้อมูลทดสอบ กด “โหลดชุดทดสอบ” เพื่อทดลองครูและผู้ตรวจ ข้อมูลอยู่ในหน่วยความจำและหายเมื่อปิดเซิร์ฟเวอร์ ไม่ใช้การเลือกบทบาทแทน Google login ในระบบจริง ไม่สร้างรายงานหรือส่งอีเมลบน Google จากโหมดนี้

กรณีพอร์ตถูกใช้ ตั้ง `ST_PREVIEW_PORT` เป็นพอร์ตอื่นก่อนรัน

ดู [หลักฐานทดสอบและรายการที่ยังต้องตรวจบน Google](docs/TEST-RESULTS.md) และ [คู่มือผู้ใช้](docs/USER-GUIDE.md)

## โครงสร้าง

`src/` คือโค้ดสำหรับ Apps Script เท่านั้น `tests/` จำลองบริการ Google เพื่อทดสอบ logic `tools/` เป็นเครื่องมือทดสอบ/จัดแพ็กเกจบนเครื่อง ห้ามอัปโหลด fixtures หรือ preview server เป็นระบบโรงเรียนจริง

ข้อจำกัดสำคัญ: Google Sheets ไม่มี transaction ข้ามชีต จึงใช้ journal, snapshot และ rollback; กระบวนการกู้คืนถูกตรวจในเครื่อง แต่ต้องซ้อมบนฐานทดสอบ Google จริง เอกสารหนึ่งฉบับมีขนาด snapshot ได้ไม่เกิน 40,000 ตัวอักษร และรายการประเมินไม่เกิน 150 รายการ คำสั่ง API ไม่เกิน 100,000 ตัวอักษร การนำเข้าไม่เกิน 500 แถวต่อครั้งและอยู่ภายในขนาดคำสั่งที่กำหนด โครงการนี้เหมาะกับข้อมูลระดับโรงเรียน ไม่ใช่ระบบข้อมูลขนาดใหญ่
